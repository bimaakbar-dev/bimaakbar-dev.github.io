[Astro Starlight](https://starlight.astro.build) is a solid documentation foundation — lightweight, MDX-based, and well-structured. But its default interface feels generic. For projects that want their own visual identity, that's a hindrance from day one.

**Stradocs** was born out of a simple frustration: *why start from scratch every time you want to be different?*

Inspired by **Fumadocs**'s clean and opinionated design approach, and **Vercel**'s precise and minimal aesthetic, Stradocs is built on one philosophy:

> **Clean. Premium. Modern.**

### Markdown Plugins

<Aside type="note">
  Astro 7 uses `@astrojs/markdown-satteri` as the default markdown processor — a Rust-based pipeline that is much faster than remark/rehype.
</Aside>

Stradocs adds two hast-based custom plugins that work at the AST level:

<CardGrid>
  <Card title="satteriExternalLink" icon="external">
    Process all external links automatically. Every outbound link from the site gets the proper attributes and visual indicators — without the author needing to write additional markup.
  </Card>
  <Card title="satteriTable" icon="list-format">
    Wraps each table in a responsive, horizontally scrollable container. Automatically applies to all Markdown and MDX content, including existing content.
  </Card>
</CardGrid>

<Aside type="tip">
  Since both plugins work at the hash AST level, their features are active across **all Markdown and MDX files** without the need to import additional components in each content file.
</Aside>

### Integrated Blog System

Starlight was designed for documentation, not blogging. Stradocs adds a fully integrated blog system—not a separate plugin, but rather part of the same project structure.

<CardGrid>
  <Card title="Blog Listing" icon="list-format">Article listing page with pagination and filtering by tags.</Card>
  <Card title="Article Page" icon="document">Detailed view of individual articles with a clean, content-focused layout.</Card>
  <Card title="RelatedPost" icon="forward-slash">Displays related articles based on similar tags below each article.</Card>
  <Card title="PopularPost" icon="star">Widget to display prioritized articles — in the sidebar or inline.</Card>
</CardGrid>

<Aside>
  Using components within blog content is the same as with Starlight. Create a `.mdx` file to use components directly within articles.
</Aside>

### Extended Schema for Blogs

Starlight's content schema is extended using the `extend` option of `docsSchema()`. All fields are optional — regular documentation pages don't need to include them.

```ts
// src/content/config.ts
schema: docsSchema({
  extend: ({ image }) => z.object({
    pubDate: z.coerce.date().optional(),
    heroImage: z.optional(image()),
    author: z.array(z.object({
      name: z.string().optional(),
      avatar: z.optional(image()),
    })).optional(),
    tags: z.array(z.string()).optional(),
  }),
})
```

Example of blog article frontmatter:

```yaml
---
title: 'Article title'
description: 'Short description.'
pubDate: 2025-09-01
author:
  - name: 'yourname'
    avatar: ~/assets/images/author/your-image.jpg
heroImage: ~/assets/images/blog/cover.jpg
tags:
  - astro
  - tutorial
draft: false
---
```

| Field | Type | Description |
|---|---|---|
| `pubDate` | `Date` (optional) | Publication date; automatically coerced from string |
| `heroImage` | `ImageMetadata` (optional) | Feature image, processed by Astro Image |
| `author` | `{ name?, avatar? }[]` (optional) | Author array — supports multiple authors with avatars |
| `tags` | `string[]` (optional) | Article categories/tags |

<Aside type="tip">
  `author` is designed as an **array** — a single article can have more than one author, each with their own name and avatar.
</Aside>

### Dual Language Support

Stradocs is configured bilingually from the start: **English** as the root and **Indonesian** in `/id`.

In addition to Starlight's built-in i18n routing, the blog component's UI strings can also be fully translated via the i18n schema extension:

```ts
schema: i18nSchema({
  extend: z.object({
    'blog.PostAuthor': z.string().optional(),
    'blog.relatedPostLabel': z.string().optional(),
    'blog.PopularPostLabel': z.string().optional(),
    'rss.RssFeedLabel': z.string().optional(),
    'rss.RssFeedTitle': z.string().optional(),
    'rss.RssFeedDesc': z.string().optional(),
  }),
})
```

There are no hardcoded strings inside the components — everything is translatable.
